# Datasets

Everything the project trains or scores on lives here. **Nothing in this
directory is committed to Git except this README** — synthetic data is
regenerated on demand, and public datasets are far too large (and often too
licence-restricted) to store in a repository.

## Bundled synthetic sample (`synthetic_sample.csv`)

Generated by `backend/app/data/synthetic.py`:

```bash
cd backend
python -c "from pathlib import Path; from app.data.synthetic import write_sample_csv, label_distribution; \
p = Path('../data/datasets/synthetic_sample.csv'); write_sample_csv(p, seed=42); print(label_distribution(__import__('pandas').read_csv(p)))"
```

or from the dashboard (**Model → Retrain → synthetic**), or via the API:

```bash
curl -X POST http://127.0.0.1:8000/datasets/generate-sample
```

Shape: one row per message, columns
`device_id, timestamp, temperature, humidity, energy_w, voltage, current_a,
rssi, status, connection_attempts, reading_count, label, source`.

`label` is `normal` or one of the five scenarios
(`message_flood`, `sensor_spike`, `telemetry_blackout`, `connection_storm`,
`unauthorized_access`); roughly 8 % of rows are abnormal. Generation is fully
deterministic for a given seed.

## Public datasets

| id | dataset | place the file at | notes |
|----|---------|-------------------|-------|
| `ciciot2023` | CICIoT2023 (105 devices, 33 attack classes) | `data/datasets/ciciot2023.csv` | Multi-GB. Canadian Institute for Cybersecurity, UNB — read its terms of use before downloading or redistributing. |
| `mqtt_iot_ids_2020` | MQTT-based IoT IDS 2020 (N-BaIoT-style MQTT captures) | `data/datasets/mqtt_iot_ids_2020.csv` | Public research dataset; check the source page's licence. |

Download pages are listed by the API (`GET /datasets`) and in
`backend/app/data/dataset_loader.py`.

### Why public datasets train in a separate feature space

CICIoT2023 and similar sets describe **flow/packet statistics**, not the
per-message sensor readings the live pipeline sees. A model trained on them is
therefore trained in `feature_space = "dataset"`: it can score that dataset's
own rows offline, and the runtime detector **refuses** to serve it for live
inference (that would be silent train/serve skew). The live detector is always
trained in `feature_space = "stream"`.

### Loading a CSV

```bash
curl -X POST http://127.0.0.1:8000/model/train \
     -H 'Content-Type: application/json' \
     -d '{"dataset":"csv","csv_path":"ciciot2023.csv","label_column":"label"}'
```

### Loading a Parquet file

The loader chooses CSV or Parquet from the file extension and accepts absolute
paths on the machine running the backend, for example:

```bash
curl -X POST http://127.0.0.1:8000/model/train \
     -H 'Content-Type: application/json' \
     -d '{"dataset":"parquet",
          "dataset_path":"D:\\datasets\\ciciot2023_train.parquet",
          "label_column":"label",
          "limit_rows":50000}'
```

`limit_rows` is a reproducible random sample (`random_state=42`), not the first
N rows. Omit it for the default 50,000 rows, or set it to `0` to load every row.
For CICIoT2023 the explicit target is the binary `label` column (0 = benign,
1 = attack); `Label` and `attack_class` are excluded from model input.

Dataset-space models are saved as versioned `backend/app/ml/artifacts/offline/
<version>.joblib` and `<version>.json` files. They are **offline only**: they do
not replace or activate the stream model used by the live MQTT detector, and no
active-model database record is changed.

Metrics are reported only when a ground-truth label column exists, and only on
a held-out stratified split.
