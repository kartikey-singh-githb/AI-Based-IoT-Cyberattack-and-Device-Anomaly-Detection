# Dataset Guide

This guide explains every dataset the P310 project can train on, where to get
it, its licence conditions, and exactly how it is loaded and preprocessed. It
complements `data/datasets/README.md` (the operational summary) with the
end-to-end procedure.

Nothing here is downloaded automatically. Public datasets are large and often
licence-restricted, so you fetch them yourself and place a CSV under
`data/datasets/`. Only `README.md` and the bundled `synthetic_sample.csv` are
committed to Git.

## Dataset families

| Family | ids | Availability | Feature space |
|---|---|---|---|
| Synthetic (project-generated) | `synthetic_sample` | Always (regenerate on demand) | `stream` — real live-pipeline features |
| Public IoT intrusion-detection | `ciciot2023`, `mqtt_iot_ids_2020` | You download manually | `dataset` — offline flow/packet features only |

The distinction matters: a `dataset`-space model is **refused for live
inference** by the detector, because flow statistics cannot be reproduced from
the per-message telemetry the streaming pipeline sees. Training such a model is
for offline evaluation of the detection approach, never for serving the
dashboard.

## 1. Synthetic sample (`synthetic_sample`)

Generated by `backend/app/data/synthetic.py`. Deterministic for a given seed;
~8 % abnormal rows across five labelled scenarios.

```bash
cd backend
python -c "from pathlib import Path; from app.data.synthetic import write_sample_csv, label_distribution; \
p = Path('../data/datasets/synthetic_sample.csv'); write_sample_csv(p, seed=42); \
print(label_distribution(__import__('pandas').read_csv(p)))"
```

Or via the API / dashboard:

```bash
curl -X POST "http://127.0.0.1:8000/datasets/generate-sample?n_devices=8&rows_per_device=400&seed=42"
```

Columns: `device_id, timestamp, temperature, humidity, energy_w, voltage,
current_a, rssi, status, connection_attempts, reading_count, label, source`.
`label` ∈ {`normal`, `message_flood`, `sensor_spike`, `telemetry_blackout`,
`connection_storm`, `unauthorized_access`}.

Train (this is the same path the dashboard uses):

```bash
curl -X POST http://127.0.0.1:8000/model/train \
     -H 'Content-Type: application/json' \
     -d '{"dataset":"synthetic","label_column":"label"}'
```

## 2. Public datasets

### CICIoT2023 (`ciciot2023`)

* **Source**: Canadian Institute for Cybersecurity (CIC), University of New
  Brunswick.
* **Download**: <https://www.unb.ca/cic/datasets/iot-2023.html>
* **Licence**: Released for research use. Read and follow the dataset page's
  terms before downloading or redistributing; it is not public domain.
* **Shape**: IoT network-flow statistics — duration, protocol, flags,
  packet/byte counts, header lengths, IAT statistics, rates — plus a label.
* **Place file at**: `data/datasets/ciciot2023.csv` (extract the subset you
  need; the full release is multi-GB).

### MQTT-IoT-IDS2020 (`mqtt_iot_ids_2020`)

* **Source**: Published research dataset (Bahrami et al.).
* **Download**: <https://github.com/AliAhmadBahrami/MQTT-IoT-IDS2020>
* **Licence**: Check the linked repository for its current licence and citation
  requirements.
* **Shape**: MQTT session/packet records — packet sizes, inter-arrival times,
  MQTT flags/QoS/topic statistics — plus attack labels.
* **Place file at**: `data/datasets/mqtt_iot_ids_2020.csv`.

Inspect what the API knows about each dataset (including whether the file is
present, its row count and size):

```bash
curl http://127.0.0.1:8000/datasets
curl http://127.0.0.1:8000/datasets/ciciot2023
```

## 3. Loading and preprocessing

`backend/app/data/dataset_loader.py` implements the whole path:

1. **Resolve** the dataset by registry id, bare filename, or absolute path
   (`resolve_path`).
2. **Read** the CSV with pandas (`load_frame`), optionally limiting rows.
3. **Detect the label column** from a candidate list (`detect_label_column`).
4. **Detect the shape** (`is_telemetry_shaped`) — whether the CSV exposes the
   streaming sensor columns (`temperature`, `humidity`, `energy_w`, `voltage`,
   `current_a`, `rssi`; ≥2 required).
5. **Build the matrix** (`prepare_dataset_matrix`): drop identifier/label/IP
   columns, keep numeric columns, drop constants and unique-per-row identifiers,
   replace infinities, impute missing values with the training median, cap width
   at the most-variable 60 columns, and map arbitrary labels onto binary
   normal/attack.

Metrics (precision/recall/F1 etc.) are reported **only** when a genuine
ground-truth label column survives — and only on a held-out stratified split —
so an unlabelled CSV never produces fabricated scores.

## 4. Training on a CSV

```bash
curl -X POST http://127.0.0.1:8000/model/train \
     -H 'Content-Type: application/json' \
     -d '{"dataset":"csv","csv_path":"ciciot2023.csv","label_column":"label"}'
```

The resulting model's feature space depends on the CSV's shape: a
telemetry-shaped CSV (sensor columns) is trained in `stream` space and can serve
live inference; a flow/packet CSV such as CICIoT2023 is trained in `dataset`
space and will not be used to score live telemetry. Retrain with
`{"dataset":"synthetic"}` to restore a live-serving `stream` model.
